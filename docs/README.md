# Ninja Dashboard documentation

## Start here

- `../README.md` — project overview and development entry points.
- `architecture.md` — cross-module boundaries, ownership, and dependency
  direction.
- `requirements.md` — root scope and acceptance criteria.
- `operations.md` — deployment, maintenance, and recovery procedures.
- `current-state.md` — verified state only; check its status date first.
- `decisions/` — durable root architectural decisions.

## Module documentation

- `../operations/docs/architecture.md` — Operations-specific architecture.
- `../operations/docs/requirements.md` — Operations scope and acceptance.
- `../operations/docs/operations.md` — Operations runbooks and validation.
- `../operations/docs/decisions/` — Operations architectural decisions.

## Historical material

- `archive/` preserves superseded plans, proposals, working notes, and
  historical root documents. It is reference material, never automatic context.
- `reference/` contains external specifications and retained development
  reference data; it is not archival history.
- `records/` contains retained maintenance and audit records.
