## Implemented

- `ingest/evaluator.py` computes a shared `LifecycleResult` per selected
  Computer, recording reason, qualified evidence, evaluation time, thresholds,
  uncertainty, blockers and separately qualified offline duration. Lifecycle
  updates, coverage offline guards, cleanup and offline findings use it.
- Qualified lifecycle evidence requires an active matching entity/platform
  observation. Contactless polling is not positive contact. Unknown/conflicting
  evidence prevents new unsupported transitions and clearing; explicit negative
  reports with unknown duration do not create extended-offline findings.
- Overlapping tenant evaluations acquire a session advisory lock before the
  repeatable-read input snapshot; rollback/unlock precedes pool return. Failures
  retain the existing failed-run reporting path, without new automatic replay.
- Explicit valid confirmed use restores requirement checks during cleanup,
  including no-agent Computers, while preserving OS, source, identity, handling
  and clearing rules. Confirmation alone does not restore a silent retired
  Computer or establish recovery from an old offline episode.
- Requirement recovery uses the coverage pass's verdicts and fresh assessments,
  replacing duplicate profile SQL and fixed 48-hour closure. Cleanup exclusion
  precedes the no-agent exclusion; retained history is not blanket-closed.
- Offline opening/recovery now runs for single-Computer and full evaluations.
  Root recovery includes investigating episodes, and respects suppression and
  existing policy-based clearing. Current uncertain roots remain open.
- `ingest/requirement_state.py:summarize_state` provides a read-only aggregate
  explanation of current guarded retention versus entries requiring review.
  Existing raw checks/counts/history are retained; the summary is callable by
  authorized diagnostics and does not clear or conceal drift.
- New pending migration `0356_requirement_episode_identity` matches full
  tenant/Computer/entity/platform/condition-key identity. It also fixes SQL NULL
  handling that could hide a covered finding with no verdict. It replaces the
  existing invoker-security function without changing its signature or grants,
  rewriting historical findings, adding tables or changing verdict vocabulary.
- Operations displays `N/A — Cleanup` instead of implying every cleanup
  Computer is offline. Historical `N/A — Offline` requirement-filter values
  remain accepted; ordinary source-record `Offline` is unchanged.

The old source-withdrawal lifecycle entrypoint now delegates to the shared
result/writer. Existing contact-policy helpers remain the authority for evidence
selection and thresholds; the production diagnostics pass does not run a second
lifecycle update. PLAN-003's ledger/relationship redesign stays outside scope.
