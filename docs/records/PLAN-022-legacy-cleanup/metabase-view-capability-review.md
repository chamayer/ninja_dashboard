# PLAN-022 Wave B — Metabase-era view capability review (2026-10-28)

Eight ingest-maintained views had no reader after Metabase's retirement. Before
deciding whether to drop them, each was checked against **what it was built
for** and **where Operations delivers that now**, in the code, not in the
parity audit. Nothing is dropped by this review.

Production measurement (L21, `select10-roles-views.txt`): the five
materialized views total about 42 MB. Ingest refreshes three of them after
every activity run, `device_troubleshooting_signal` after every Ninja run,
and `latest_device_health` after every health run. The three custom-field
views are plain views, regenerated by every custom-field run.

## Correction to the parity audit

`operations/docs/metabase-parity-audit.md` (2026-10-12) marked these as
**Displayed** or **Consolidated**, but the routes it names do not show them:

- Patch Trends (`/patching/trends/`) shows installs, failures, failure rate,
  attempts and devices touched per day from `ninja_patches.patch_facts`, which
  covers Patch Installs per Day, Failed Install Attempts per Day and Patching
  Devices per Day. It does not show System Reboots per Day, OS Patch Warnings
  per Day, or OS Patch Operational Failures per Day (Ninja
  `PATCH_MANAGEMENT_FAILURE` activity events, not install outcomes). No page
  shows Currently-MANUAL Patches by Age: Patch Evidence lists Manual patches
  but does not age them.
- Warning cards (Command Center "OS Patch Warnings (24h)"; Client Patch Review
  "Warnings (30d)"; Device Work Queue "With Warnings", "Warnings by Category
  (30d)", "Top Devices by Warnings (30d)", "Devices Matching Warning Category
  (30d)"; Device Detail "Recent OS Patch Warnings (30d)"): `/patching/` has no
  warning tile or filter. The device timeline lists raw events but does not
  answer "warnings in the last 30 days".

The audit is corrected in place, with the affected rows marked **Missing**.

## Outcome

- Keep all eight views. The materialized ones still back gaps, and the
  refresh cost is small. Revisit the drop once each gap below is built in
  Operations or the user declines it.
- Backlog (root `TODO.md`): patch warning analysis, reboot and patch-activity
  trends, and Ninja device-health display. Custom-field display waits for an
  operator need.
- `device_troubleshooting_signal` may not be refreshing at all (row estimate
  −1). That doesn't matter while nothing reads it; it gets checked before the
  view is reused or dropped.
