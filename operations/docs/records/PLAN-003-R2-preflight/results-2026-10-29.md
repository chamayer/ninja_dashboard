## Integrity

- Admin assessments: 1,112 rows, **4 reference no admin finding**; admin
  participants: 712 rows, **4 unresolved**. Entity assessments (191,190) and
  participants (160,966) all resolve. The 8 orphans need an explicit M2
  disposition (retain as orphaned audit rows or remove with a recorded reason).
- `finding_state` and `source_action_requests`: zero tenant mismatches, so the
  R1 `NOT VALID` FKs can be validated in M2.

## Implications for R2

- Copying ~1,350 admin rows is small; any whole-table work on `findings`
  (~618,000 rows) needs measured timing in rehearsal and runs with ingest drained.
- Subject normalization covers 18 shapes; types with structured non-UUID subjects
  need `subject_id` NULL plus a validated `subject_ref`.
